# 近地面平滑减速（10 m 缓冲）/ Smooth Near-Ground Descent Cap (10 m Buffer)

面向 **ArduCopter 4.6.3 / 4.7.0** 的 Lua 脚本：在 **AltHold(2) / Loiter(5)** 模式下，按
**EKF 相对 home 点的高度**平滑收紧飞行员手动下降速度参数。与同目录的阶梯版不同，本脚本在
**10 m 到 5 m** 之间用 smoothstep 曲线渐进收敛，避免在固定高度突然收紧带来的掉高与振荡。

脚本只修改下降速度参数，**不发送 arm / disarm / 电机 / 模式指令**；落地靠固件原生
`DISARM_DELAY` 自动上锁。

> 高度取自 `ahrs:get_relative_position_NED_home()`，是**相对 home 点的高度，不是对地真实高度**。
> 地形起伏、气压漂移、home 点偏差都会影响判定结果。

---

## 功能概述 / Overview

| 文件 | 说明 |
| --- | --- |
| `near_ground_slowdown_smooth_10m_stage2_0p2.lua` | 10 m 缓冲渐变限速版：10–5 m 平滑收敛到 0.50 m/s，≤ 2 m 限 0.20 m/s |
| `near_ground_slowdown_smooth_10m_stage2_0p2.md` | 本说明文档 |

核心行为：

- 高度 ≥ 10 m：不限制，直接使用原始下降参数。
- 10 m → 5 m：沿 smoothstep 曲线由原始有效速度平滑收敛到 0.50 m/s。
- 5 m 以下：0.50 m/s 档；2 m 以下：0.20 m/s 档。
- 高度数据故障（EKF 异常、home 未设置、调度卡顿等）：强制 0.10 m/s 保守档。
- 4.6.x 的 `AP_Int16` 参数会截断小数 cm/s，本脚本写入前统一向下取整到整数 cm/s，且最小写 1，
  绝不因取整而放大限值，也绝不写入 0（`0` 在固件中表示“沿用 UP 值”）。

## 限速策略 / Speed Profile

设 R 为原始有效下降速度（`DN = 0` 时取 UP 换算值），h 为相对 home 高度：

```text
L    = min(R, 0.50)
s    = clamp((h - 5) / 5, 0, 1)
lim  = L + (R - L) · s² · (3 − 2s)        -- smoothstep，两端斜率为 0
```

| 相对 home 高度 | 目标下降速度上限 |
| --- | --- |
| ≥ 10 m | 原始参数（不限制） |
| 10 m → 5 m | 沿 smoothstep 曲线由 R 连续收敛到 0.50 m/s |
| 5 m ≥ 高度 > 2 m | 0.50 m/s |
| ≤ 2 m | 0.20 m/s |
| 高度/数据故障 | 0.10 m/s |

以原始有效速度 R = 1.00 m/s 为例：

| 高度 | 曲线位置 s | 下降速度上限 |
| --- | --- | --- |
| 10.0 m | 1.00 | 1.000 m/s（不限） |
| 9.0 m | 0.80 | 0.948 m/s |
| 7.5 m | 0.50 | 0.750 m/s |
| 6.0 m | 0.20 | 0.552 m/s |
| 5.0 m | 0.00 | 0.500 m/s |
| 2.0 m | — | 0.200 m/s |

说明：

- 曲线两端导数为零，因此进入 10 m 与抵达 5 m 时都不会出现速度阶跃，降落过程中不会因参数突变而掉高。
- 若原始有效速度 R ≤ 0.50 m/s，曲线退化为“不限制”——原本就比限值更慢，无需干预。
- 10–5 m 区间为连续缓冲区，脚本上报状态码 **10**；5 m 以下仍是离散档位（状态码 1 / 2 / 3）。
- 高度回升时，5 m 与 2 m 档位仍按 **0.3 m 滞回 + 持续 500 ms** 才放松，防止在档位边界抖动。

## 适用固件与参数适配 / Firmware Adapter

| 固件 | 下降参数 | 上升参数 | 单位换算 |
| --- | --- | --- | --- |
| 4.6.x | `PILOT_SPEED_DN` | `PILOT_SPEED_UP` | cm/s，除以 100（整数参数） |
| 4.7.x | `PILOT_SPD_DN` | `PILOT_SPD_UP` | m/s，除以 1（浮点参数） |

- 脚本要求**两组参数有且仅有一组存在**。两者都不存在或同时存在时报
  `unsupported descent parameter adapter` 并只做监视，不写任何参数。
- 仅适配 ArduCopter 4.6.3 与 4.7.0；其他版本未做兼容处理，参数名称或语义变化可能导致脚本失效。
- 4.6.x 在整数 cm/s 上工作，本脚本对目标值做向下取整并保证 ≥ 1，避免“取整后低于目标”或误写 0。

## 相关参数 / Parameters

脚本自身读写的原生参数：

| 参数 | 作用 | 说明 |
| --- | --- | --- |
| `PILOT_SPEED_DN` / `PILOT_SPEED_UP` | 4.6.x 手动下降 / 上升速度 | 单位 cm/s，整数；`DN = 0` 表示沿用 `UP` |
| `PILOT_SPD_DN` / `PILOT_SPD_UP` | 4.7.x 手动下降 / 上升速度 | 单位 m/s，浮点；`DN = 0` 表示沿用 `UP` |
| `DISARM_DELAY` | 落地后自动上锁延时 | 为 0 或读不到时无自动上锁，脚本每 10 s 告警 |
| `SCR_ENABLE` | Lua 脚本引擎使能 | 必须为 1，否则脚本不运行 |

脚本注册的恢复参数表（`param:add_table(192, 'NGC_', 14)`，字段顺序即索引 1..14）：

| 索引 | 名称 | 含义 |
| --- | --- | --- |
| 1 | `NGC_VER` | 结构版本（当前 2） |
| 2 | `NGC_ADAPTER` | 参数适配器编号（46 / 47） |
| 3 | `NGC_BASE` | 原始下降参数值 |
| 4 | `NGC_UP` | 原始上升参数值 |
| 5 | `NGC_EXPECT` | 脚本认为参数当前应等于的值 |
| 6 | `NGC_PVAL` | 写前意图值 |
| 7 | `NGC_PEND` | 是否存在未确认的写入意图 |
| 8 | `NGC_READY` | 基线是否完整建立 |
| 9 | `NGC_BLOCK` | 是否因外部修改而让出控制 |
| 10 | `NGC_OWNER` | 实例编号（多实例互斥） |
| 11 | `NGC_UNKN` | 原始值未知（只收紧） |
| 12 | `NGC_CEIL` | 保守/未知模式下的固定曲线参考速度 |
| 13 | `NGC_ACK` | 落地人工确认（唯一允许手动修改的字段） |
| 14 | `NGC_MAGIC` | 魔数 602902，用于识别本脚本创建的表 |

> 除 `NGC_ACK` 外，**不要手动修改任何 `NGC_*` 参数**。
> 在未知原始值模式下，`NGC_CEIL` 作为曲线的**固定参考速度**参与计算；若误把它改成实时收紧后的值，
> 会导致悬停在同一高度时速度被反复压低。

## 安装 / Installation

1. 将 `near_ground_slowdown_smooth_10m_stage2_0p2.lua` 放入飞控 SD 卡的 `APM/scripts/` 目录
   （文件名可保持不变）。
2. 确认 `SCR_ENABLE = 1`，且 `SCR_HEAP_SIZE` 足够（脚本会注册 14 个参数、写飞行日志；
   若日志出现 `recovery table unavailable` 说明参数表/堆空间不足）。
3. 同目录下另外两个近地减速脚本**不可与本脚本同时加载**：三者共用同一张 `NGC_` 参数表
   （table key `192`、魔数 `602902`），同时加载会互相覆盖恢复记录并争夺控制权。
4. 上电后检查地面站消息中以 `NGS:` 开头的输出，确认脚本已运行；地面未解锁时应看到
   `HOME height; ... original=...` 的基线记录提示。

## 使用流程 / Workflow

**正常流程（地面加载）**

1. 地面未解锁加载脚本 → 脚本把当前下降参数记为基线，写入 `NGC_*` 恢复表。
2. 起飞后在 AltHold / Loiter 中按上述曲线自动限速；其它模式（Auto / Land / RTL 等）交还固件原生逻辑。
3. 落地、`DISARM_DELAY` 自动上锁 → 脚本自动把参数还原为原始值，并重建基线。

**原始值未知（空中首次加载 / 记录损坏 / 读参失败）**

- 进入 `tighten only` 模式：**只允许收紧，绝不向上放大**，状态码 8；此时 `NGC_CEIL` 固定为曲线参考。
- 落地后需人工核对/恢复原生下降参数，然后在**未解锁**状态把 `NGC_ACK` 置 `1`。
- 脚本只接受“先看到 0、再看到 1”的新上升沿：解锁期间写入的 ACK 会被清零并提示
  `NGC_ACK ignored while armed`；VM 启动时就存在的 ACK 也不被承认。

**`DISARM_DELAY` 为 0 或读不到时**：落地不会自动上锁，脚本每 10 s 告警一次
`DISARM_DELAY disabled/unknown; native auto-disarm unavailable`。

## 状态码 / State Codes

状态码写入飞行日志的 `State` 字段，便于复盘：

| 状态码 | 含义 |
| --- | --- |
| 1 | 未限速（使用原始参数） |
| 2 | 0.50 m/s 档 |
| 3 | 0.20 m/s 档 |
| 4 | 高度数据故障，0.10 m/s 保守档 |
| 5 | 非目标模式（非 AltHold / Loiter） |
| 6 | 让出控制 / 参数异常 |
| 7 | 初始化未完成或状态未知（只监视） |
| 8 | 原始值未知，只收紧 |
| 9 | 已落地，等待 `NGC_ACK` 确认 |
| 10 | 10–5 m 缓冲曲线生效（本脚本新增） |

## 飞行日志 / Logging

脚本以 5 Hz（节流 200 ms）写入日志消息 `NGSL`，与同目录其它脚本格式一致：

```text
NGSL, Height, Limit, VDown, Mode, State    (格式 fffBB)
```

- `Height`：相对 home 高度（m），无效时写 NaN
- `Limit`：本周期实际生效的下降速度上限（m/s），无效时写 NaN
- `VDown`：NED 下降速度（m/s）
- `Mode`：当前飞行模式编号，未知时写 255
- `State`：上表状态码

地面站文本消息统一以 `NGS: ` 前缀，级别 3 = error，4 = warning，6 = info。缓冲区间内提示为
`buffer 10-5m`，其余为 `limit x.xx m/s`。

## 安全设计 / Safety Design

1. **不接管飞行控制**：只写 `PILOT_SPEED_DN`（或 `PILOT_SPD_DN`），不发送 arm/disarm/电机/模式指令。
2. **原始值未知只收紧**：空中首次加载、记录损坏等情况下 `ceiling` 只会取更小值，绝不放大参数。
3. **外部修改即让出**：检测到参数被外部改动立即停止写入（`NGC_BLOCK = 1`），直到解锁后重建基线。
4. **写前意图 + 写后读回**：每次写原生参数前先记录 `PVAL` / `PEND`，写入后读回校验；中途掉电也能在下次启动识别。
5. **整数量化安全**：4.6.x 写入前向下取整到整数 cm/s 且最小为 1，既不放大限值，也不会把有效限速写成 0。
6. **提交式记录**：`NGC_READY` 先清零、逐字段写入、最后置 1；中途断电会被判定为记录不完整并转保守。
7. **异常不退出**：采样与主逻辑全部包 `pcall`，单次异常只导致本周期进入最紧档，脚本继续运行。

## 选用建议 / Which Variant

- **优先考虑本脚本**：起飞高度较高（> 10 m）、希望在进入近地前就逐步收速，减少 5 m 处突然限速造成的
  掉高、下沉加速或飞手感突兀；或使用 4.6.3 且原始下降速度不是整数 m/s，需要整数量化保护。
- **选 `near_ground_slowdown_stage2_0p2.lua`**：希望限速逻辑简单可预测、只在 5 m 以下介入，
  且 2 m 以下保留 0.20 m/s 的手感。
- **选 `near_ground_slowdown.lua`**：场地狭窄、机体贵重，需要 2 m 以下最软的 0.10 m/s 接地。
- **切换版本时**：先卸载当前脚本 → 落地确认参数已还原为原始值 → 再放入新脚本并重新建立基线。
  不要借助同一张 `NGC_` 表跨版本“热切换”，三者的档位逻辑不同，残留记录不能直接复用。
